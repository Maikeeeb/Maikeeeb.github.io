The starting point

Why build it?

Small CLI programs repeat the same input loop: ask, convert, explain an error, and try again. A shared helper reduces duplication.

My contribution

What I built.

I built ask(prompt, **restrictions) with explicit type conversion, allowed answers, exclusive minimum/maximum bounds, string case normalization, and length checks.

End to end

How it works.

  1. 1

    Read and convert

    Prompt and apply the requested type.

  2. 2

    Explain errors

    Check restrictions and print feedback.

  3. 3

    Return a value

    Repeat until the answer satisfies the configured checks.

For a closer technical review

Decisions & tradeoffs.

Open each note for the implementation boundary, tradeoff, and next engineering question.

01Flexible keywords have a cost

kwargs is concise but makes unsupported combinations and misspelled keys easy to miss. Typed keyword-only parameters or a validated restriction object would make the contract more discoverable.

02Validate the validator’s configuration

The demonstrated path supplies type=int. Omitting type can leave the implementation retrying indefinitely, and mixed type/length restrictions can raise errors. Reject invalid configuration before prompting rather than treating it as bad user input.

Scope & next steps

What this demonstrates.

Learning library, not a hardened package. EOF, cancellation, missing types, contradictory restrictions, and boundary semantics need explicit regression tests.
