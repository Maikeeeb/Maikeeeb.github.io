The starting point

Why build it?

Parallel research becomes difficult to audit when agents repeat work or conclusions lose their evidence. The workflow needs persistent artifacts and checks between stages.

My contribution

What I built.

I developed custom agent instructions and standard-library Python helpers for initialization, status, handoff validation, duplicate-question gates, cross-artifact checks, and Markdown compilation.

For a closer technical review

Decisions & tradeoffs.

Open each note for the implementation boundary, tradeoff, and next engineering question.

01Separate process control from judgment

Python owns folders, checkpoints, validation order, subprocess exit codes, and resumability. Agents own decomposition, evidence interpretation, and synthesis. Deterministic validation is not a fact-checking oracle.

02Artifacts are the source of truth

The workflow checks agreement among plans, question trees, handoffs, and source mappings instead of trusting one status flag. This supports inspection and resumption. Schema consistency alone cannot establish that a source supports a claim.

Scope & next steps

What this demonstrates.

Local orchestration tooling. Duplicate heuristics can miss paraphrases, and structurally valid evidence can still be wrong. Trace checks should be evaluated against deliberately unsupported claims.
