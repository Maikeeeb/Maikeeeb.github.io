The starting point

Why build it?

An interface should not be the only place that decides whether a value is allowed. A board model makes the rules reusable and independently testable.

My contribution

What I built.

I built a Sudoku interface and implementation with row, column, and 3×3-cell checks, guarded updates, and a BasicIO form for entering moves and refreshing the board.

For a closer technical review

Decisions & tradeoffs.

Open each note for the implementation boundary, tradeoff, and next engineering question.

01The model owns the move constraint

isAllowed combines row, column, and cell checks; update calls it before assignment. Coordinate and value-range validation still need to be added at the boundary.

02Encapsulation affects correctness

The model accepts and returns array references, allowing callers to bypass guarded updates. Defensive copies or a narrower cell API would protect the invariant. Generation and solving should remain separate from move validation.
