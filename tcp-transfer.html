Why build it?

For a closer technical review

Decisions & tradeoffs.

Open each note for the implementation boundary, tradeoff, and next engineering question.

01TCP has no message boundaries

The receiver assumes its first recv contains only the metadata header. TCP can split the header or combine it with body bytes, so a successful local run does not prove robust framing. A length-prefixed header and exact-byte reads would make the contract explicit.

02Completion needs stronger checks

The receiver writes until connection closure. It should verify expected size, limit uploads, handle truncation, and write to a temporary file before promotion. Authentication and encryption would be necessary for a remote service.
