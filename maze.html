For a closer technical review

Decisions & tradeoffs.

Open each note for the implementation boundary, tradeoff, and next engineering question.

01Why visited state matters

A maze with loops must distinguish unexplored cells from previously visited locations. Otherwise recursion can repeat a cycle indefinitely. This is the central idea described in the archived portfolio.

02What a restored version should verify

A restored build should cover no-exit mazes, boundary starts, invalid rows, and large open regions. An explicit stack avoids call-stack limits. These are review targets, not claims about the missing implementation.
